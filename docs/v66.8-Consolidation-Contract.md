# v66.8 — Consolidated Kitchen Operations Contract

## Purpose

The UI should not need to understand or coordinate every KOS service.

`kos.kitchen` is now the stable presentation-facing facade.

## Primary calls

- `kos.kitchen.home()` — consolidated kitchen state
- `kos.kitchen.intent(id)` — data for one of the eight user intentions
- `kos.kitchen.health()` — verifies required services are available

## Supported intent IDs

- dinner
- plan-week
- cook
- freezer-meals
- available
- shopping
- recipes
- learn

## Benefit

Future homepage, desktop, iPad, or phone interfaces can change independently from the underlying KOS services.
